### 4.3 The acceptance command

```
BREEV_M2_ACCEPTANCE_EVIDENCE=1 pnpm --filter @breev/desktop test:acceptance:m2
```

`test:acceptance:m2` resolves to `playwright test --config playwright.acceptance.config.ts` (`apps/desktop/package.json:19`). The tracked bundle in `acceptance/` was regenerated through the publish wrapper `test:acceptance:m2:publish` → `node scripts/regenerate-m2-acceptance.mjs` (`package.json:20`), which sets the opt-in variable for you and — because a run that fails partway must never leave a half-regenerated bundle — restores `evidence/issue-59/acceptance/` on any failure: tracked files go back with `git checkout`, files the run itself created are deleted, and files that existed beforehand are left alone.

Prerequisites, all of them mandatory:

1. **Windows** — the harness launches the win32 packaged artifact.
2. **`pnpm build && pnpm package:desktop`** — `artifacts/Breev-win32-x64/Breev.exe` and `apps/local-api/dist/main.js` must exist at the commit under test.
3. **Docker**, for the Testcontainers PostgreSQL fixture.

It is **deliberately outside CI**. The workflow's packaged smoke job runs on Linux against `Breev-linux-x64`; a Windows runner would have to build and package the desktop, start Docker Linux containers, and drive a GUI Electron artifact over CDP inside one job, and a green result there would still not be the client-facing Windows artifact unless the runner packaged win32. Keeping it a local, explicitly-invoked milestone command also matches the acceptance-issue shape: it runs once, for a named commit, and its output is committed as evidence rather than recomputed per push. Without `BREEV_M2_ACCEPTANCE_EVIDENCE=1` the harness writes to the git-ignored `test-results` tree, so an ordinary run can never overwrite the tracked bundle.

### 4.4 The ten flows per pass

Each of the four passes (`en`/`ar` × light/dark) runs these ten Playwright tests, serially, in the order the transcript records them:

1. clause 1 — defines an item and finds it by smart search
2. clause 2 — saves a supplier invoice with cost and price per pricing mode
3. margin scenario — 80 at 20% is 100, and rounding applies only when enabled
4. clause 3 — an adjustment records only the difference, and a return is separate
5. clause 4 — quantities, batches and expiry in inventory, stocktaking and the basket
6. reorder from sales — the draft is byte-identical before and after
7. bilingual pass — direction, theme and keyboard operation, on its own REST-created draft
8. adjustment scenario — 4 to 8 posts exactly +4, unchanged lines are silent, invalid Delta blocked and measured in view
9. scope — the item-details panel in purchasing, measured in the packaged window
10. units scenario — one pack is four strips, a stocktake of 2 packs + 1 strip is 9, and the base-unit column measured in the packaged window

Ten tests yield **eleven** transcript records per pass, because test 1 writes both the `clause-1` record and the `scenario-search` record. 11 × 4 = 44.

**The acceptance run on `e73b541` failed the scope item, and the run on `7dda434` failed the Units scenario's own subject.** Under `docs/delivery.md` ("A defect is an implemented function that does not meet the approved written requirement or agreed acceptance outcome; corrections to reach compliance are included") all three are milestone-2 defects, fixed and re-run inside this milestone, not carried forward and not change requests.

**Fix:** commit `7dda434`, "fix(purchasing): keep the item-details panel and correction refusals in view". The sidebar becomes the one panel, fed from the selected row; the workspace grid no longer grows to the table's min-content width; below 80rem the panel is a sticky band that stays in view on long invoices; refusals in the adjustment and return workflows scroll into view and take focus through the committed-focus pattern. Renderer and CSS only.

**Independent review (WF-1-R)** returned CHANGES_REQUIRED on the first cut and all three points were applied: H-1 the sticky band at ≤80rem plus a twelve-row assertion, M-1 an axe scan of the populated panel, M-3 `tabIndex={-1}` on the aside. WF-1-R also recorded M-2: scope §6.1 says "left item-details panel", and the build uses `inset-inline-end`, which is the left edge in Arabic (the Arabic-first prototype) and mirrors correctly in English — keep the logical property, do not hard-code a side.

**Second fix (WF-2), commit `1d229d4`**, "fix(purchasing): fit every invoice column in the window and keep sections stacked". `.purchase-row-table` takes a fixed layout with a per-field width budget (ordinal 3rem, quantity 5.5rem, cost and selling 7rem each, expiry 10rem, base units 9rem, the item name absorbing the rest), inputs at `width: 100%; min-width: 0`, every cell carrying `data-column-field`, and a clipped committed item name exposing its full text as a `title`. The seven default columns now fit at 1024, 1066 and 1280 px with no horizontal scroll; the wrapper keeps its scrollbar only as a safety net for extreme text scaling. Renderer and CSS only, again.

**Two layout regressions the first fix had introduced, repaired in the same commit.** Above the 80rem breakpoint the row-table wrapper collapsed to `clientHeight 0`; after a `min-block-size: max-content` band-aid it instead overflowed into the sections below it. The root fix is `grid-auto-rows: max-content` on `.purchase-row-workspace`, with the workspace scrolling vertically. **Neither was caught by the suites or by the independent review — both were found only by opening the regenerated screenshots.** The lesson is recorded verbatim in plan §8: _"per-element geometry assertions miss collapsed or overlapping containers; someone must open the screenshots."_ The guard added for it is `expectWorkspaceSectionsStacked` (`purchasing.browser.test.ts:1970`), which requires consecutive workspace children never to overlap.

## 11. Test-harness follow-ups (portability and hygiene, not product defects)

Five items, all in test code. None changes product behaviour, and none was changed under this issue.

1. **Local-API readiness deadlines are marginal on this workstation.** The shared browser helper `apps/desktop/test/local-api-process.ts:90-115` allows **15 s**, and `apps/local-api/src/purchasing/purchase-posting.integration.test.ts:2450` allows **60 s**, for the local API's cold start against a fresh Testcontainers PostgreSQL. Both hold when the host is free and lose the race under concurrent load; `batch-safety.browser` loses it first because its `beforeAll` fixture is the heaviest (Testcontainers PostgreSQL, bootstrap, a posted purchase and a second user before the renderer starts). Fix shape: make both deadlines configurable, or raise them. No timeout anywhere in the repository was weakened for this issue.
2. **POSIX-only `SIGKILL` assertion.** `apps/local-api/src/inventory/inventory-safety.integration.test.ts:531` asserts `(await child.waitForExit()).signal === "SIGKILL"`. The crash worker self-terminates with `process.kill(process.pid, "SIGKILL")`; Windows has no POSIX signals, so Node maps it to `TerminateProcess` and the parent observes `{ code: 1, signal: null }` (probed on this host). The same kill pattern passes here where the test asserts on durable state instead (`apps/local-api/src/sales/sale-draft.integration.test.ts:154`, case 3 — 7/7). The identical assertion also sits in `apps/local-api/src/identity-access/settings-crash.integration.test.ts:243, :274, :309`, outside the W2 list, and would fail here for the same reason. Fix shape: assert exit _or_ signal, per platform.
3. **`pnpm package:windows:payload` picks up GNU tar instead of Windows bsdtar.** `apps/local-api/windows/prepare-payload.mjs:241` shells out to `tar`; this machine's PATH puts Git for Windows' GNU tar 1.35 ahead of `C:\Windows\System32\tar.exe` (bsdtar), and GNU tar parses `D:\path` as `host:path`, so it fails with exit 128. A clean Windows CI runner has System32 first. Fix shape: resolve the Windows `tar.exe` explicitly rather than trusting PATH.
4. **A browser suite writes into tracked `evidence/` on a plain run.** `apps/desktop/test/browser/purchasing.browser.test.ts:66-90` resolves six tracked directories directly (`evidence/purchases-prototype-alignment/after`, `evidence/issue-18/after`, `evidence/issue-50/after`, `evidence/issue-51/after`, `evidence/issue-52/after`, `evidence/issue-53/after`) instead of going through `apps/desktop/test/browser/evidence-path.ts`, so it ignores `BREEV_REGENERATE_EVIDENCE` and overwrites the committed audit record on every ordinary run. It is the only file in `apps/desktop` that does this. W2's `e73b541` sweep left 39 tracked files dirty under `evidence/` as a result; they were restored with `git checkout -- evidence` inside the lane worktree. The `7dda434` re-run handled it by restoring the six directories after **each** browser suite, and `git status --short -- evidence` afterwards reported nothing outside `evidence/issue-59/`. The four `evidence/purchases-prototype-alignment/after/purchase-selected-*.png` files refreshed in **each** fix commit are the same mechanism used deliberately — both fixes genuinely change what that screen looks like, so HEAD already holds the intended new images. Fix shape: route the suite through `evidencePath()` like every other suite.

5. **A session-expiry integration test is timing-sensitive by construction.** `apps/local-api/src/identity-access/identity-access.integration.test.ts:2478`, in "survives restart and rejects expired, revoked, and wrong-device sessions", expires the session from outside the application right after a concurrent-login step — `update identity_sessions set expires_at = created_at + interval '1 millisecond'` — and then requires the next request to report `session-expired` rather than `unauthenticated`. Which of the two the server reports depends on how that write and the in-flight session interleave, so a loaded runner can flip it: it did, once, in CI `verify` job 105862401643 (§7), and passed on the identical commit in job 105864536231 as well as in 104305613667, 105762911738 and 105850110060. **Pre-existing** — the code under it is byte-identical to `e73b541` (`git diff --stat e73b541..1d229d4 -- apps/local-api packages/contracts` is empty) — and therefore not a defect of this milestone. Fix shape: expire the session with a deterministic clock or poll for the expected state instead of asserting once on a millisecond boundary.
