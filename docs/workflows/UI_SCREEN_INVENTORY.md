## Recovered shared UI requirements

- The dense Arabic pharmacy workstation layout and quick-action hierarchy are valuable reference material.
- Every core screen needs AR/EN copy, RTL/LTR mirroring, light/dark tokens, keyboard/focus rules, loading/empty/error/offline/disabled states, permission denial, entitlement upgrade state, and audit feedback.
- Destructive “delete” affordances on posted/stock/accounting records become explicit return/reversal/archive flows.
- Cost/profit, exports, overrides, backdating, and corrections are hidden and rejected unless the actor has the named permission.
- Browser `localStorage` may retain harmless per-device presentation preferences only; it cannot be the authoritative store for drafts, aliases, images, clinical records, settings, schedules, or integration notes.
- Future modules should not appear as active core navigation just because placeholder routes exist.

## Route gaps required by the target architecture

The prototype has no complete screens for local user login/lock/recovery, device pairing/revocation, plan/entitlement status, subscription billing, update channel/maintenance-window/deferral/health and repair history, local/cloud backup and restore-drill health, certified hardware/peripheral diagnostics and print-failure reprint, high-risk action requests/dual-control approvals, accessibility/performance evidence and diagnostics, privacy requests/holds/outcomes, patient export, time-limited support grants/review, cloud incident/status and Restore Quarantine evidence, sync status/conflicts, audit explorer, safe invoice correction chain, batch-level stock ledger, clinical mapping/content-freshness/evaluation evidence, external payment attempts/settlement/refunds/disputes, tax-submission evidence, or minimal Super Admin. These are requirements gaps, not permission to add them during Phase 0.
