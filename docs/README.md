# Project Documentation

## Phase 0 discovery set

- `context/PROJECT_CONTEXT.md` — source authority, product/architecture baseline, scope and decision gates.
- `context/SOURCE_INVENTORY.md` — inspected sources, repository evidence, route/data/build findings.
- `domain/GLOSSARY.md` and `/CONTEXT.md` — canonical domain language.
- `requirements/REQUIREMENTS_REGISTER.md` — traceable confirmed, pending, deferred, and excluded requirements.
- `requirements/CONTRADICTION_REGISTER.md` — source conflicts and reconciliations.
- `workflows/UI_SCREEN_INVENTORY.md` — every prototype route and its disposition.
- `workflows/UI_WORKFLOW_MAP.md` — recovered target workflows and invariants.
- `workflows/KEYBOARD_WORKFLOWS.md` — confirmed high-speed sequences and open bindings.
- `architecture/MODULE_MAP.md` — proposed apps/modules/packages and dependency rules.
- `questions/OPEN_QUESTIONS.md` — one-at-a-time Phase 0 decision queue.
- `risks/RISK_REGISTER.md` — discovery risks and gates.
- `decisions/ADR-001` through `ADR-027` — architecture decisions, including stakeholder-approved naming, offline licensing, LAN/device trust, conditionally approved patient/clinical-data policies, WhatsApp/OCR, external-payment/e-invoicing, and provisional cloud-operations, Windows/hardware, update-safety, authorization, external-integration, and performance/accessibility boundaries.
- `plans/MASTER_DELIVERY_PLAN.md` — phases and approval gates.
- `plans/PHASE_1_TASK_PROPOSAL.md` — reviewable foundation tasks, eligible after Phase 0 approval and explicit initiation.
