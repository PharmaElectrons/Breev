## Authority and status rules

The source hierarchy in [the documentation baseline](README.md#source-authority) governs. The exact M2 allocation in [the delivery plan](delivery.md#milestone-2-items-purchases-and-inventory--14-days-450), the governing scope's [Milestone 2 section](requirements/breev-phase1-mvp-scope.md#132-milestone-two-items-purchases-and-inventory), and later explicit stakeholder decisions recorded in #190 outrank prototype surfaces and broad Phase One capability lists. Issues #45–#58 decompose that scope; their closed state is evidence history, not authority to ignore a current defect. Closed acceptance issue #59 is historical evidence, while #190 requires current remediation and revalidation.

Statuses mean:

- **proven** — current implementation and an executable automated seam exist, no current audit defect is known for this bounded record, and prior evidence demonstrates the behavior. A fresh current-commit package run is still required by M2-Q04.
- **defect** — the implementation, test coverage, presentation, or current-candidate evidence is known to differ from the requirement.
- **external gate** — the implementation uses an explicitly unapproved working default or cannot receive final acceptance until the named external owner approves it.
- **deferred** — the capability is outside M2 and must not contribute to its grade or visible client promise.
